Stage 1 — Phase 1.3
Candidate Profile Agent

What I Built

In Phase 1.3, I built the first functional CPIP agent — the Candidate Profile Agent. This agent reads raw student data and transforms it into a structured, normalized profile that other agents can use.

The Three Components

  • ✅ Agent Code — Python function that normalizes student data into structured format
  • ✅ API Endpoint — FastAPI routes to call the agent from the web
  • ✅ Validation — Logic to verify the profile is complete and valid

Data Transformation

Input (Raw Student Data):

{ "id": 1, "name": "Arathy Rajeev", "email": "arathy@gmail.com", "degree": "BBA", "cgpa": 7.0, "location": "Kochi", "target_role": "AI Engineer", "github_link": "https://github.com/arathy26", "salary_expected": 500000 }

Output (Structured Profile):

{ "candidate_id": 1, "name": "Arathy Rajeev", "contact": { "email": "arathy@gmail.com", "location": "Kochi" }, "academics": { "degree": "BBA", "cgpa": 7.0 }, "career": { "target_role": "AI Engineer", "salary_expectation": 500000 }, "portfolio": { "github": "https://github.com/arathy26", "linkedin": null, "resume": null } }

Career & Placement Domain Learning

I learned that data quality is the foundation of intelligent placement systems.

Key Insight:

Raw student data from forms/databases is scattered and unorganized. A placement agent cannot work with messy data. The first agent must clean, normalize, and structure the data so downstream agents receive consistent, usable input.

Why This Matters in Placement

When a mentor or placement officer needs to evaluate a student, they don't want raw database records. They want:

  • ✅ Organized student profile (not scattered fields)
  • ✅ Clear academic information grouped together
  • ✅ Career goals highlighted
  • ✅ Portfolio links in one place

The Candidate Profile Agent does exactly this — it transforms chaos into clarity.

Agentic AI Learning

I learned that in agentic systems, the first agent's job is data normalization.

The Agent Principle:

Each agent has ONE specific job. The Candidate Profile Agent's job is: Read messy data → Normalize it → Output clean structure. It doesn't evaluate, score, or recommend. It just cleans.

Agent Orchestration Flow

Raw Student Data ↓ Candidate Profile Agent ├─ Normalizes student info ├─ Groups related fields ├─ Validates completeness ↓ Structured Candidate Profile ↓ (Other Agents Use This) ├─ Skill Gap Agent (analyzes skills) ├─ Portfolio Agent (evaluates projects) ├─ Role Matching Agent (recommends roles) ↓ Final Placement Recommendation

Why This Architecture Works: Each agent is simple and focused. Agent 2 doesn't need to understand raw data — it receives clean data from Agent 1. This is how agentic systems scale.

Known Limitations

⚠️ Sample Data (Not Real Database):

For Phase 1.3 MVP, we used hardcoded sample data in the API route. This was intentional for testing. In Phase 1.14+, we'll connect to the real STUDENT table in the database. For now, we've proven the agent logic and API structure work.

✅ This Is Acceptable Because:

We're testing the agent's transformation logic and API communication, not the database. The agent code is independent of data source — it will work the same way when connected to real database.

Key Takeaway

Data normalization is the foundation of agentic AI systems.

Before an agent can evaluate, score, or recommend, the data must be clean, organized, and structured. The Candidate Profile Agent does this foundational work. It's simple, focused, and essential. This is what separates agentic AI from simple scripts — coordination between specialized agents, each with clear input and output contracts.
