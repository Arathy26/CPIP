What I Built

In Phase 1.5, I built the third CPIP agent — the Portfolio Readiness Agent. This agent evaluates whether a student's portfolio evidence (GitHub, deployed demo, project explanation, LinkedIn) is complete and interview-ready.

Career & Placement Domain Learning

I learned that portfolio evidence is what proves students can build things.

Key Insight:

"Projects without evidence are just words." In real placement, talking about skills is not enough. A student must SHOW GitHub repos, deployed demos, and project explanations. A portfolio readiness score tells students exactly what evidence is missing so they can improve before applying to jobs.

Why Portfolio Matters in Placement

Without portfolio evidence:

  • ❌ Students claim they can build but have nothing to show
  • ❌ Employers can't verify student abilities
  • ❌ Interviews are weak because no real project to discuss

With portfolio readiness analysis:

  • ✅ Students know exactly what evidence to collect
  • ✅ Employers see real proof of capability
  • ✅ Interviews are strong with live demos and GitHub projects

Agentic AI Learning

I learned that agentic systems evaluate data against rules and classify results.

The Classification Principle:

The Portfolio Readiness Agent doesn't just store data — it EVALUATES it. For each portfolio item (GitHub, demo, README, LinkedIn), it checks: Present or Missing? Then it calculates a score and classifies readiness (High/Medium/Low). This classification is what downstream agents (Training Recommendation, Interview Readiness) need to make decisions.

How Agents Coordinate

Candidate Profile (Phase 1.3) ↓ Skill Gap Agent (Phase 1.4) ├─ Produces: Gap Score, Missing Skills ↓ Portfolio Readiness Agent (Phase 1.5) ├─ Evaluates: Evidence present/missing ├─ Produces: Portfolio Score, Missing Evidence ↓ (Phase 1.6+: Other agents use this) ├─ Resume Readiness Agent │ → "Mention your projects on resume" ├─ Interview Readiness Agent │ → "Practice demoing your GitHub projects" └─ Training Recommendation Agent → "Build and deploy a project first"

Key Functions

portfolio_readiness_agent(portfolio_data):

Takes student portfolio data, checks each evidence type (GitHub, demo, README, LinkedIn), and returns portfolio score (0-100), evidence present, evidence missing, and readiness level.

Two API Endpoints

Endpoint 1: Single Student Portfolio

GET /portfolio-readiness/1

Returns portfolio analysis for student 1, including score and missing evidence

Endpoint 2: All Students Portfolio

GET /portfolio-readiness

Returns portfolio scores and readiness for all 3 sample students

Known Limitations

⚠️ Sample Portfolio Data (Not Real Database):

For Phase 1.5 MVP, portfolio data is hardcoded in the API route. This was intentional for testing. In Phase 1.14+, we'll query real portfolio data from the database. For now, we've proven the evaluation logic works correctly.

✅ This Is Acceptable Because:

We're validating the evidence evaluation algorithm and API communication work correctly. The agent will work exactly the same way when connected to real student portfolio tables.

Key Takeaway

Agents evaluate data against rules and produce measurable outputs.

Phase 1.3 transformed data. Phase 1.4 scored data. Phase 1.5 evaluated data against rules (Present/Missing) and classified results (Portfolio Score + Readiness). Each agent's output feeds into the next agent's logic. This is how agentic AI systems scale: clear, composable, measurable outputs.
